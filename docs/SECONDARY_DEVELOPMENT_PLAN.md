# SciGraph Copilot 基础版二次开发计划

## 1. 项目定位

SciGraph Copilot 是一个面向科研文献的 AI 知识分析与可视化平台。

用户可以上传论文或文本资料，系统通过 GraphRAG 构建知识图谱；用户既可以与资料对话，也可以通过 3D 图谱和 ECharts 看板查看实体关系、主题分布和检索结果。

本次二次开发的目标不是做大型商业系统，而是完成一个功能完整、技术重点明确、可以用于简历和面试演示的项目。

## 2. 与岗位要求的对应关系

| 岗位要求 | 项目中的实现 |
| --- | --- |
| React/Vue、TypeScript | 使用现有 Next.js、React、TypeScript |
| AI 大模型 Web 应用 | 文档问答、流式输出、模型配置 |
| AI4Science 可视化平台 | 科研文献、实体关系和主题分析 |
| 对话交互 | Chat 面板、SSE 流式回答、错误提示 |

## 3. 当前项目基础

当前代码已经具备：

- Next.js 16、React 19 和 TypeScript。
- Three.js、React Three Fiber 和 `d3-force-3d` 3D 图谱。
- Microsoft GraphRAG 3.1。
- OpenAI 和 Ollama 模型配置。
- 文档上传、索引构建、项目归档和日志查看。
- GraphRAG 查询和 SSE 流式聊天。
- 图谱搜索、节点选择、社区查看和实体详情。

基础版需要补充：

- 项目品牌和中文界面。
- 更清晰的页面结构。
- 基础 LangGraph 问答流程。
- 可靠的引用和图谱联动。
- ECharts 数据分析看板。
- 可量化的图谱性能优化。
- 基础测试和项目文档。

## 4. 基础版功能范围

基础版只完成以下四个核心页面：

1. **项目与文档**：上传资料、选择模型、启动知识图谱构建、查看日志。
2. **AI 问答**：围绕已上传资料提问，查看流式回答和引用。
3. **知识图谱**：查看实体、关系、社区和 AI 回答关联节点。
4. **数据看板**：通过 ECharts 查看文献、实体、社区和关系统计。

暂不开发：

- 多租户、付费、权限管理。
- WebGPU 和百万级数据。
- 复杂多 Agent 系统。
- Embedding Atlas 集成。
- 完整数据库后台。
- 多个 AI4Science 行业模板。

## 5. 技术方案

```text
React / Next.js / TypeScript
├─ 项目与文档管理
├─ AI 对话界面
├─ ECharts 数据看板
└─ Three.js 3D 知识图谱
            │
            ▼
Next.js API / SSE
            │
            ▼
基础 LangGraph 工作流
├─ 接收问题
├─ 调用 GraphRAG 检索
├─ 整理引用和实体
└─ 返回答案
            │
            ▼
Microsoft GraphRAG / OpenAI / Ollama
```

LangGraph 与 GraphRAG 的分工：

- LangGraph 负责安排问答步骤。
- GraphRAG 负责文档索引和知识检索。
- Next.js 负责页面 API 和流式事件转发。
- 不引入复杂的多 Agent、长期记忆和人工审批流程。

## 7. 分阶段计划

## 阶段 1：项目整理与基础工程化

### 目标

先保证项目能够稳定安装、启动和构建，并完成基础品牌改造。

### 开发任务

- 将页面中的 GraphRAG Workbench 名称替换为 SciGraph Copilot。
- 增加中文标题、菜单和主要操作提示。
- 更新 README，说明项目定位、技术栈和启动步骤。
- 新增 `.env.example`，但不提交真实 API Key。
- 确认 OpenAI 和 Ollama 两种配置方式。
- 检查并修复 TypeScript、ESLint 和生产构建错误。
- 保持 `main` 为稳定版本，后续开发在 `develop` 分支进行。

### 验收标准

- `pnpm install` 可以完成依赖安装。
- `pnpm dev` 可以启动项目。
- `pnpm typecheck`、`pnpm lint`、`pnpm build` 通过。
- 首页显示 SciGraph Copilot 品牌。
- README 可以指导新用户完成启动。

## 阶段 2：AI 问答与基础 LangGraph

### 目标

让用户能够围绕项目文档进行稳定、可解释的流式问答。

### 开发任务

- 新增一个简单的 Python LangGraph 工作流。
- 工作流只包含四个主要步骤：
  1. 接收并校验问题；
  2. 调用现有 GraphRAG 查询；
  3. 提取关联实体和引用；
  4. 返回答案和执行状态。
- Next.js Chat API 调用 LangGraph 工作流。
- 沿用现有 SSE，在前端显示回答生成过程。
- 增加“停止生成”功能。
- 回答中展示引用文档或来源片段。
- 点击引用时，高亮相关知识图谱节点。
- 保留 local、global、drift 等查询模式选择。
- 对模型不可用、检索失败和无结果提供明确提示。

### 简化状态图

```text
开始
  ↓
校验问题
  ↓
调用 GraphRAG
  ↓
整理引用与实体
  ↓
返回流式答案
  ↓
结束
```

### 验收标准

- 用户可以成功发送问题并看到流式答案。
- 用户可以停止一次正在执行的请求。
- 回答至少能展示来源名称或证据片段。
- 点击回答中的实体或引用能够联动图谱。
- LangGraph 节点执行顺序在界面或日志中可见。
- LangGraph 只承担实际流程编排，不做空壳包装。

## 阶段 3：ECharts 数据分析看板

### 目标

补齐岗位明确要求的数据可视化和复杂图表能力。

### 开发任务

- 安装并按需引入 ECharts。
- 新建 Analytics 页面。
- 封装通用 ECharts React 组件，支持自动缩放、加载和空状态。
- 第一版实现五类图表：
  1. 实体类型分布柱状图；
  2. 社区节点数量饼图或矩形树图；
  3. 关系类型桑基图；
  4. 文献或主题变化趋势图；
  5. 实体关联强度热力图。
- 增加 tooltip、legend、dataZoom 和导出图片功能。
- 点击图表数据后过滤或高亮图谱节点。
- 图谱选中节点后更新相关统计图表。
- 数据量较大时使用 Canvas、sampling、progressive 或 large 模式。

### 验收标准

- 至少五类 ECharts 图表能够使用当前项目数据。
- 至少两张图表与知识图谱实现双向联动。
- 窗口和面板尺寸改变时图表能正常 resize。
- 图表组件卸载后不残留事件监听器。
- 图表能够导出为图片。

## 阶段 4：知识图谱功能与性能优化

### 目标

在现有 Three.js 和 d3-force-3d 基础上，增强图谱交互，并形成真实的性能优化结果。

### 开发任务

- 保留现有 3D 图谱，不另外引入第二套图谱框架。
- 增加实体类型、社区和关系权重筛选。
- 增加搜索定位、邻居高亮和关系路径查看。
- 将较重的数据转换或布局计算移入 Web Worker。
- 继续使用分批挂载，优先显示重要节点和关键关系。
- 对远距离节点减少标签和细节，降低渲染负担。
- 减少不必要的 React 重渲染和 Three.js 对象创建。
- 生成 1,000、5,000、10,000 节点的模拟数据进行测试。
- 记录首个图谱出现时间、布局耗时、FPS 和内存占用。

### 基础性能目标

- 1,000 节点能够流畅交互。
- 5,000 节点下缩放和旋转无明显长时间卡死。
- 10,000 节点数据可以完成加载，并通过筛选控制显示规模。
- 节点点击后的界面反馈时间尽量控制在 200ms 内。

以上指标必须实测；未达到时记录当前结果和原因，不虚构性能数据。

### 验收标准

- 搜索、筛选、选中、高亮和 Inspector 功能正常。
- Web Worker 工作期间页面仍可进行基本操作。
- 有一份优化前后性能对比记录。
- AI 回答、ECharts 和 3D 图谱共享实体选择状态。

## 阶段 5：AI4Science 演示场景

### 目标

让项目不只是通用知识库，而是能够体现科研平台业务。

### 开发任务

- 选择一个简单科研主题，例如药物、疾病和靶点关系。
- 准备少量公开论文或摘要作为演示资料。
- 定义基础实体类型，例如：
  - Paper；
  - Drug；
  - Disease；
  - Target；
  - Experiment。
- 调整 GraphRAG 提示词，使实体抽取更符合该领域。
- 增加文献来源、摘要和关键实体展示。
- 设计三个固定演示问题。
- 完成“上传资料—构建图谱—AI 提问—查看引用—图谱定位—看板分析”的完整流程。

### 验收标准

- 至少一套公开科研演示数据可以重复导入和构建。
- 三个演示问题能够得到有引用的回答。
- 回答、图谱和 ECharts 看板可以形成完整联动。
- README 标明演示数据来源，不提交有版权风险或敏感数据。

### 验收标准

## 8. 开发优先级

如果时间有限，按以下顺序保证核心功能：

1. 项目能够运行和构建。
2. AI 流式问答和基础 LangGraph。
3. 回答引用与知识图谱联动。
4. ECharts 分析看板。
5. 图谱性能测试与优化。
6. AI4Science 演示数据。
7. 测试、截图和演示视频。

前三项构成 AI 平台核心，第四和第五项直接对应岗位的数据可视化与性能要求。
