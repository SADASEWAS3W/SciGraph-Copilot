# SciGraph Copilot 前端分阶段开发计划

## 1. 计划目标

本计划从 `docs/SECONDARY_DEVELOPMENT_PLAN.md` 中提取前端与数据可视化工作，作为前端负责人独立执行和跟踪的开发计划。

前端最终交付一个可演示的 AI4Science Web 平台界面，覆盖项目与文档管理、AI 问答、3D 知识图谱和数据看板，并完成回答、引用、实体、图表与图谱之间的联动。

主要代码范围：

```text
app/page.tsx
components/**
hooks/**
lib/graphData.ts
lib/forceSimulation.ts
前端样式、图表组件和 Web Worker
```

Agent、GraphRAG 和服务端实现不属于本计划的开发范围。涉及这些模块的内容仅作为接口依赖和联调条件列出。

## 2. 当前基础与主要缺口

| 模块 | 当前基础 | 需要完成的前端工作 |
| --- | --- | --- |
| 主页面 | 已有全屏 3D 图谱、节点选择、Inspector 和基础筛选状态 | 补充产品导航、页面入口、共享选择状态和响应式布局 |
| AI 对话 | `ChatPanel.tsx` 已有输入、查询模式、消息展示和流式读取逻辑 | 挂载到主页面，完善面板状态、取消、错误、引用和实体联动 |
| 项目与配置 | 已有 `CorpusPanel` 和 `ProviderSetupDialog` | 统一中文文案、加载态、空状态、错误提示和操作反馈 |
| 数据看板 | 当前依赖中有 Recharts，但没有 ECharts | 确认使用 ECharts 后增加依赖，建设五类科研分析图表 |
| 3D 图谱 | 已有 Three.js、React Three Fiber 和 d3-force-3d 实现 | 增加搜索、路径、邻居交互及 1k/5k/10k 性能优化 |
| 测试与演示 | 已有类型检查、Lint、构建和 Agent Harness | 补充核心前端测试、性能记录、截图和演示流程 |

## 3. 阶段总览

| 阶段 | 目标 | 预计工期 | 核心里程碑 |
| --- | --- | --- | --- |
| 阶段 1 | 基线整理与契约冻结 | 3～5 天 | 页面可运行，Mock 流程可联调 |
| 阶段 2 | AI 流式问答与引用联动 | 1 周 | 完成真实问答主流程 |
| 阶段 3 | ECharts 科研数据看板 | 1 周 | 五类图表和跨视图联动 |
| 阶段 4 | 3D 图谱交互与性能优化 | 1～2 周 | 形成可复现的性能数据 |
| 阶段 5 | AI4Science 演示场景 | 3～5 天 | 跑通完整科研业务闭环 |
| 阶段 6 | 测试、文档与作品化 | 3～5 天 | 通过质量门禁并完成展示材料 |

总工期预计 4～6 周。每个阶段都以可演示、可联调的用户流程为结束条件。

## 4. 分阶段执行计划

### 阶段 1：基线整理与契约冻结

目标：建立稳定的前端结构和 Mock 数据，使前端不依赖 Agent 服务进度也能完成页面开发。

开发任务：

- [ ] 盘点 `app/page.tsx`、`ChatPanel`、`CorpusPanel`、`ProviderSetupDialog`、`GraphVisualizer` 和 `Inspector` 的现有职责。
- [ ] 明确四个核心功能入口：项目与文档、AI 问答、知识图谱、数据看板。
- [ ] 完成 SciGraph Copilot 品牌、中文菜单和基础响应式页面结构。
- [ ] 统一加载、空数据、失败、无结果和可重试状态组件。
- [ ] 将 AI 问答事件、索引状态、引用、实体和图谱对象映射为严格 TypeScript 类型。
- [ ] 准备小、中、大三组前端固定数据，以及完整问答事件序列 Mock。
- [ ] 核对浏览器端环境变量使用，确保页面和日志不显示密钥、服务端路径或敏感配置。
- [ ] 确认 ECharts 的版本与按需加载方式，记录依赖变更方案。

交付物：

- 前端页面信息架构和基础导航。
- 第一版共享类型及 Mock 数据。
- 通用状态组件和前端错误文案规范。
- 前端启动、Mock 切换和联调说明。

Agent 侧依赖：冻结 AI 问答 SSE 事件、索引状态、错误码、引用结构和实体结构。

验收标准：

- 页面可正常启动并访问四个功能入口。
- Mock 问答可以依次播放 `run_started`、`node_started`、`token`、`citations`、`entities` 和 `done`。
- 缺少配置、数据为空和接口失败时均显示失败操作及可执行的恢复动作。
- Mock 对象的实体 ID 可被对话、图表和图谱共同识别。

建议分支：`feature/frontend-foundation`

### 阶段 2：AI 流式问答与引用联动

目标：完成可发现、可停止、有过程、有引用的文献问答体验。

开发任务：

- [ ] 在 `app/page.tsx` 挂载现有 `ChatPanel`，增加清晰的 AI 问答入口。
- [ ] 实现桌面侧边栏和移动端抽屉，并处理打开、关闭、宽度和焦点状态。
- [ ] 整理对话状态机：空闲、连接中、生成中、停止中、完成和失败。
- [ ] 完善消息列表、输入框、local/global/drift 查询模式及发送约束。
- [ ] 消费流式事件并展示增量答案、Agent 节点步骤、耗时和完成状态。
- [ ] 使用 `AbortController` 实现停止生成，并在卸载、重试和新请求时清理旧连接。
- [ ] 为超时、模型不可用、检索失败、连接中断和无结果提供可恢复反馈。
- [ ] 开发引用卡片，展示文档名、证据片段和来源标识。
- [ ] 开发实体标签或卡片，点击后定位并高亮 3D 图谱节点。
- [ ] 将图谱当前选中实体反馈给对话上下文，并避免保存可从已有状态推导的数据。

交付物：

- 主页面 AI 问答入口和响应式对话面板。
- 完整流式消息与 Agent 步骤展示。
- 停止、重试、错误恢复、引用和实体联动。
- 问答主流程的组件或交互测试。

Agent 侧依赖：真实 `/api/chat/stream` 调用链路；稳定的流式事件顺序；Abort、错误码、引用和实体返回。

验收标准：

- 用户能从图谱页面打开和关闭 AI 问答，移动端无内容遮挡。
- 回答可以流式显示并停止，停止后不会继续追加 Token。
- 每次有效回答至少显示来源或证据片段。
- 点击回答中的实体可定位图谱；图谱选中实体可作为下一次提问的上下文。
- 连接、订阅和计时器在关闭或重试时正确释放。

建议分支：`feature/frontend-chat`

### 阶段 3：ECharts 科研数据看板

目标：提供可解释的科研图表，并与 AI 问答和 3D 图谱共享实体状态。

开发任务：

- [ ] 增加 ECharts 依赖并采用按需引入，避免整包进入首屏。
- [ ] 封装统一图表容器，处理初始化、`ResizeObserver`、加载、空状态、错误和销毁。
- [ ] 实现实体类型柱状图。
- [ ] 实现社区矩形树图。
- [ ] 实现关系桑基图。
- [ ] 实现主题趋势图。
- [ ] 实现实例强度热力图。
- [ ] 补充 tooltip、legend、dataZoom 和图片导出。
- [ ] 实现图表点击筛选图谱，以及图谱选中实体后更新图表状态。
- [ ] 对大数据图表启用 Canvas、sampling、progressive 或 large 模式，并记录启用条件。

交付物：

- 独立数据看板入口和统一 ECharts 组件。
- 至少五类使用真实数据结构的图表。
- 至少两张图表与 3D 图谱双向联动。
- 图表数据转换函数和关键交互测试。

Agent 侧依赖：实体、关系、社区、文档聚合数据；稳定 ID；空值及异常数据约定；固定联调样例。

验收标准：

- 图表随容器尺寸变化正确重排，无重复实例和事件监听。
- 数据为空、缺字段和请求失败时页面保持可用。
- 图表点击后图谱筛选或定位正确，返回图谱时选择状态不丢失。
- 大样例下页面无明显长时间主线程阻塞。

建议分支：`feature/frontend-dashboard`

### 阶段 4：3D 图谱交互与性能优化

目标：增强复杂图谱探索能力，并用实测数据说明不同规模下的表现。

开发任务：

- [ ] 增加实体类型、社区层级和关系权重筛选。
- [ ] 完成实体搜索、镜头定位、邻居高亮和关系路径展示。
- [ ] 统一对话、图表、Inspector 和 3D 图谱的选中实体状态。
- [ ] 分析 `lib/graphData.ts` 与 `lib/forceSimulation.ts` 的主线程耗时。
- [ ] 将适合后台执行的数据转换或布局计算迁移到 Web Worker。
- [ ] 实现分批挂载、标签降级、几何体与材质复用，控制 draw calls 和内存占用。
- [ ] 清理动画帧、Worker、事件监听、Three.js 几何体、材质和纹理资源。
- [ ] 建立 1k、5k、10k 节点测试场景，记录数据体积、加载时间、布局耗时、FPS、交互延迟和内存。
- [ ] 根据实测结果设定自动降级条件，例如标签密度、边显示数量和社区边界精度。

交付物：

- 完整的图谱搜索、筛选、高亮和路径交互。
- Worker 与分批渲染方案。
- 1k、5k、10k 性能报告，包含测试环境和复现方法。
- 性能优化前后对比数据。

Agent 侧依赖：轻量图谱数据、实体邻居和路径查询、无重复及无悬空关系的数据，以及标准性能样例。

验收标准：

- 1,000 节点可流畅交互。
- 5,000 节点不会长时间卡死，并可正常筛选和选择。
- 10,000 节点能够加载，并通过筛选或降级控制显示规模。
- 点击反馈以 200ms 为目标；未达到时记录实测值、瓶颈和下一步方案。
- 页面切换或数据重载后无持续增长的动画帧、监听器和 WebGL 资源。

建议分支：`feature/frontend-graph-performance`

### 阶段 5：AI4Science 演示场景

目标：将已有能力串成招聘方或新用户可直接理解的科研分析流程。

开发任务：

- [ ] 制作文献、实体、引用和统计数据的完整演示状态。
- [ ] 优化“回答 → 引用 → 图谱 → 看板”的操作路径和返回路径。
- [ ] 增加首次使用引导、示例问题、步骤提示和结果说明。
- [ ] 统一中文术语、按钮文案、错误反馈和空状态。
- [ ] 检查桌面和移动端关键路径，避免面板互相遮挡或失去选中状态。
- [ ] 准备页面截图、录屏脚本和可重复的前端演示步骤。

交付物：

- “上传资料 → 构建图谱 → AI 提问 → 查看引用 → 定位图谱 → 看板分析”演示流程。
- 三个示例问题及对应操作路径。
- 页面截图和 2～3 分钟演示录屏素材。

Agent 侧依赖：可合法使用且可重复构建的公开数据；三个稳定问题；预期引用和实体结果。

验收标准：

- 演示数据重复构建后，前端主要视图和交互仍能正常工作。
- 三个示例问题都能进入引用、图谱和看板分析路径。
- 用户在不阅读代码的情况下可以理解每一步的目的和结果。

建议分支：`feature/frontend-demo`

### 阶段 6：测试、文档与作品化

- [ ] 补充核心 E2E 路径：打开对话、流式回答、停止、查看引用、定位实体和图表联动。
- [ ] 检查首屏体积、动态加载、重复渲染和大数据交互表现。
- [ ] 检查移动端布局、键盘操作、焦点管理和常用控件可访问名称。
- [ ] 检查所有定时器、订阅、事件监听、Worker、图表和 Three.js 资源释放。
- [ ] 整理前端架构说明、功能截图、性能报告和人工验收步骤。
- [ ] 与 Agent 负责人完成一次全链路人工验收。

- 前端架构说明和性能报告。

- GitHub 首页可以快速说明产品价值、技术难点和实测结果。

建议分支：`feature/frontend-release`

## 5. 阶段间依赖与联调顺序

```text
共享契约与 Mock
        ↓
AI 问答入口与流式状态
        ↓
共享实体选择状态
      ↙   ↘
ECharts   3D 图谱交互
      ↘   ↙
完整 AI4Science 演示
        ↓
一次性质量门禁与作品化
```

前端每阶段结束时完成以下交接：

1. 更新共享类型，或明确说明本阶段没有契约变化。
2. 提供可联调的前端页面、真实接口或固定 Mock。
3. 在 Pull Request 中写明功能、风险和人工验证步骤。
4. 将遗留问题登记为 Issue，并标记为前端、Agent 或共同任务。

契约变更应先合并再修改消费者。不要让前端页面直接依赖 GraphRAG 原始文件格式或服务端内部字段。

## 6. 前端完成定义

一个前端阶段只有同时满足以下条件才算完成：

- 用户入口明确，主路径可以从界面完整执行。
- 加载、空数据、失败、取消和完成状态都有可理解反馈。
- TypeScript 类型明确，没有新增 `any`。
- 定时器、订阅、事件监听、动画帧、Worker、ECharts 和 Three.js 资源正确释放。
- 桌面端和移动端关键流程可用。
- 与 Agent 侧的输入输出符合共享契约。
- 完成必要的局部验证，但未提前重复运行完整质量门禁。
- Pull Request 使用 Conventional Commits，并包含风险及人工验证方式。

性能提升比例、节点规模、响应耗时和帧率只填写最终实测数据，不使用估算值。
